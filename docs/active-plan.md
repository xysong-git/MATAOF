## 1. 当前目标

以 Apache IoTDB 为实验平台，**产出开题报告三组对照实验的正式数据**，验证多智能体
动态查询优化方法的有效性，支撑论文撰写：
- Baseline 1：native（原生 IoTDB）
- Baseline 2：fixed（固定策略）
- Ours：agent（多智能体确定性）+ llm（LLM 增强变体，异步补写）

## 2. 核心约束（不可违反）

1. 一切决策以查询信息/数据库状态/历史记录/运行时反馈为依据；无法确定 → `unknown`，
   **绝不编造**统计/指标/结果
2. 有界策略空间：候选 = 输入候选 ∩ 固定目录（8 策略），禁止自造；每个决策可追踪
3. 安全优先：证据不足回退 baseline；高风险策略需强证据；不改数据库内核/源码
4. 知识库 append-only（不修改、不删除）；单次结果不当规律
5. 确定性核心 + LLM 只写 `llm_analysis` 附加节（失败即兜底）
6. 实验可复现：种子/run_id/口径统一；分位数只在批次/轮次汇总生成（单次不编造）

## 3. 已确认决策（不再反复讨论）

| 决策 | 结论 |
|---|---|
| 决策 Agent 输出 | 混合模型：strategy_id + 候选提供方的 equivalent_sql + 执行级参数（决策只选择、不生成 SQL） |
| baseline 机制 | 逐条配对双执行（同 Session 紧邻，公平对照）；native 模式是轮次级对照组，两者不混淆 |
| LLM 运行模式 | 默认 `async_enhance: true` + `cache_file` + `sample_rate: 10` + `async_drain_timeout: 0`（不阻塞主链路）；`preference_bonus: true` 强制同步 |
| workers 并行 | 仅同步 LLM 模式有效（实测 1.75×）；异步/无 LLM 自动降级为 1（GIL，实测反向） |
| 知识库策略 | **每轮实验用独立知识库路径**（同质查询证据饱和快，大库只有成本；51k 旧库可归档删除） |
| 配置管理 | `scripts/gen_configs.py` 是唯一事实来源（改默认参数后重新生成全部配置） |
| 汇报口径 | 批次=文件；本轮总体=调用；轮次=run_id 过滤；汇总格式与指标与每批次完全一致 |
| 旧文档定位 | perf-overhead-plan / redundancy-review / project-summary 等已标记为历史档案 |
