## 1. 当前目标

以 Apache IoTDB 为实验平台，**产出开题报告三组对照实验的正式数据**，验证多智能体
动态查询优化方法的有效性，支撑论文撰写：
- Baseline 1：native（原生 IoTDB）
- Baseline 2：fixed（固定策略）
- Ours：agent（确定性链路）+ llm（LLM 参与策略选择，确定性兜底）

## 2. 核心约束（不可违反）

1. 一切决策以查询信息/数据库状态/历史记录/运行时反馈为依据；无法确定 → `unknown`，
   **绝不编造**统计/指标/结果
2. 有界策略空间：候选 = 输入候选 ∩ 固定目录（8 策略），禁止自造；每个决策可追踪
3. 安全优先：证据不足回退 baseline；高风险策略需强证据；不改数据库内核/源码
4. 知识库 append-only（不修改、不删除）；单次结果不当规律
5. **LLM 参与决策（decision_mode="llm_primary"）**：LLM 从候选选择策略，只做
   合法性校验（候选 ∩ 目录、维度适用、需求满足；equivalent_sql 一律取自候选
   提供方——决策只选择、不生成 SQL）；LLM 失败/非法 → 确定性决策兜底。
   证据与置信度始终来自确定性链路（LLM 不给证据，防编造）
6. 实验可复现：种子/run_id/口径统一；分位数只在批次/轮次汇总生成（单次不编造）

## 3. 已确认决策（不再反复讨论）

| 决策 | 结论 |
|---|---|
| 决策 Agent 输出 | 混合模型：strategy_id + 候选提供方的 equivalent_sql + 执行级参数（决策只选择、不生成 SQL） |
| baseline 机制 | 逐条配对双执行（同 Session 紧邻，公平对照）；native 模式是轮次级对照组，两者不混淆 |
| LLM 运行模式 | llm 变体：`decision_mode="llm_primary"` 同步决策（特征化量化 prompt + 输出缓存：16500 条抽样仅 69 个唯一 prompt，缓存高命中 → 全量可行；每条查询恰好 1 次 LLM 调用，QA/监控解读关闭）；agent 变体：无 LLM。preference_bonus 为独立实验开关 |
| workers 并行 | 仅同步 LLM 模式有效（实测 1.75×）；异步/无 LLM 自动降级为 1（GIL，实测反向） |
| 知识库策略 | **统一知识库：跨规模共享 + 跨模式隔离**——dbs/dbm/dbl 共用同一库（不同数据集经验互相迁移，不重复学习）；fixed/agent/llm 各自独立（固定策略执行记录不污染对照证据）；SQLite 后端；正式对照实验每轮从同一快照出发保证可复现 |
| 配置管理 | `scripts/gen_configs.py` 是唯一事实来源（改默认参数后重新生成全部配置） |
| 汇报口径 | 批次=文件；本轮总体=调用；轮次=run_id 过滤；汇总格式与指标与每批次完全一致 |
| 旧文档定位 | 历史档案已删除（perf-overhead-plan / redundancy-review / project-summary / pipeline-flow——内容已沉淀到本文件与 run-experiment.md）；design-gap-analysis（D5~D7 设计来源）与 comparison-mapo-mataof（论文素材）保留 |
