状态：D1~D4 已按方案实施并测试通过（D5~D8 按计划延后至消融/动态负载阶段）。

实施摘要（2026-09-22）：

## 一、总体结论

当前代码已覆盖报告的核心骨架：四 Agent 分工、三维度候选空间（Time Pruning /
Filter Order / Aggregation Placement，含三类聚合位置方案）、分析→决策→执行→
反馈→更新的闭环、IoTDB 非侵入式验证平台、append-only 历史知识库——与报告
2.1/2.2/3.2 的描述**高度一致**。

差异集中在六个点，按"报告实现方法的符合度"排序：

| # | 差异点 | 报告依据 | 当前状态 | 优先级 |
|---|---|---|---|---|
| D1 | 决策 Agent 依据反馈**动态调整策略评价权重与优先级** | 2.2.3、2.4.2 | 评分权重为固定常量；KM 有统计但**不回馈到评分** | **P0** |
| D2 | 查询特征表示为**高维特征向量** | 3.3 | 结构化 JSON 特征，无向量化表示 | P0 |
| D3 | **Baseline 2：固定优化策略方法**对照实验 | 3.4.1 | 有 native（Baseline 1）与 agent，无固定策略对照模式 | P1 |
| D4 | 指标：CPU 平均与**峰值**、内存**峰值占用** | 3.5 | CPU 仅执行期平均；内存仅单次采样 | P1 |
| D5 | **模块消融实验**（剥离 QA/EM/KM） | 3.4.5 | 无模块级消融开关 | P1 |
| D6 | **动态演化工作负载实验** + **Adaptation Performance 指标**（漂移后收敛迭代次数/时间） | 3.4.4、3.5 | 查询集静态；无漂移注入；无收敛指标 | P2 |
| D7 | **策略切换跟踪实验**（与物理最优策略重合度） | 3.4.6 | 无"物理最优"oracle 测量 | P2 |
| D8 | 决策 Agent"基于特征**生成**候选策略集" | 3.2、3.3 | 固定目录 + 需求过滤（近似，但非显式特征映射） | P2（说明性） |

LLM 增强（四个 Agent 的 llm_analysis + 本地 Qwen3-8B）与报告 3.3
"研究初期不对底层决策模型做硬性限定，后续遴选综合效能最优的决策算法"方向一致，
属于已推进项，不计入差异。

## 二、逐项差异说明与修改方案

### D1（P0）：策略评价的动态权重与优先级调整

**报告原文**："Optimization Decision Agent 依据新增的执行反馈调整候选策略的
评价权重与优先级，使优化决策能够随工作负载特征与数据分布的演变逐步迭代修正。"
（2.2.3）；"将查询真实执行性能反馈引入策略选择过程……动态调整优化策略的优先级"
（2.4.2）。

**现状**：决策评分 `score = base + context + history + system [+ llm_bonus]`，
其中 history 项每次从 KM 检索的历史证据**临时计算**（相似记录加权），评分系数
是固定常量；KM 已维护 per-strategy 累计统计与 priority_change，但该统计
**只报告、不参与评分**。决策 Agent 无跨查询状态。

**修改方案**：
1. KM 新增"策略评价表"（strategy evaluation table）：
   `{(query_type, dimension, strategy): {count, success_ratio, weighted_latency,
   priority, updated_at}}`，随每次 update 原子更新（数据全部来自真实反馈）；
2. 决策 Agent 的 history 加分改为**两级**：
   - 实例级证据（现状的相似记录加权，保留）；
   - 表级先验（新增）：查询同类上下文下该策略的累计成功率/延迟表现，
     映射为有界加分（如 success_ratio×0.2），替代/补充当前
     "无实例证据时的 -0.10"惩罚；
3. priority_change 语义改为真实参与：优先级变化超过阈值时，表级先验加分
   同步增减（增量有界，如 ±0.05，可配置）；
4. 权重更新必须确定性、只依据真实反馈；初始权重 = 当前固定常量
   （保证可复现与消融可比）。

**涉及**：`knowledge_memory/store.py`（评价表持久化）、`retrieval.py`（输出评价表）、
`optimization_decision/scoring.py`（history 加分两级化）、`agent.py`（传参）、
配置项（表级先验强度）。

**原则兼容性**：权重是反馈的确定性函数，仍可复现；不删除历史、不否定单次结论，
符合"证据累积"原则。

### D2（P0）：特征向量化表示

**报告原文**："由 Query Analysis Agent 提取其物理与逻辑特征，表示为高维特征
向量：向量维度涵盖时间跨度、设备维度基数、过滤条件选择性、聚合算子类型以及
预计数据扫描范围等上下文信息。"（3.3）

**现状**：特征是结构化 JSON（time/device/filter/aggregation/scan 节），
下游决策消费结构化字段；无数值向量形式。

**修改方案**：
1. 新增 `mataof/agents/query_analysis/vectorize.py`：
   - 定义固定维度的特征编码（与历史相似度 compact 特征对齐）：
     数值维度（时间跨度 ms 对数化、设备数、过滤条件计数、选择率等）+
     独热维度（查询类型 6 类、范围等级 4 类、有无聚合/分组/窗口、
     聚合函数集合哈希桶等）；
   - 维度固定、顺序固定、缺失即 0/unknown 位（不编造）；
2. QA 输出增加 `feature_vector` 字段（扩展节），结构化特征保持不变
   （两者并存：向量供模型/实验，结构供可解释性）；
3. 报告 3.3 的"效能评估函数 E(策略|特征,历史)"：决策 Agent 保留结构化评分，
   特征向量作为未来学习模型的输入接口（接口标准化，符合报告"初期不定模型"）。

**涉及**：新增 vectorize.py、schemas 扩展、QA agent 集成、单测（维度一致性、
未知字段编码）。

---

### D3（P1）：Baseline 2 固定策略对照模式

**报告原文**："Baseline 2：固定优化策略方法"（3.4.1，与 Baseline 1 原生、
Ours 三组对照）。

**现状**：`run_experiment.sh` 支持 native（Baseline 1）与 agent（Ours），
无固定策略对照。

**修改方案**：
1. 新增 `--mode fixed`：跳过决策 Agent，对每条查询**固定执行预设策略组合**
   （配置文件 `fixed_strategy`：如 `time_pruning=full_scan,
   filter_order=time_first, aggregation_placement=final_level_aggregation`，
   可配置成多组对照），仍走监控/知识库/追踪链路以便指标口径一致；
2. 实现为 Runner 的轻量分支（决策输出直接用固定策略构造，其余链路复用）；
3. 文档补充三组对照（native / fixed / agent）的实验矩阵。

**涉及**：`runner.py`（固定策略路径）、`run_experiment.sh`、配置模板、测试。

### D4（P1）：CPU 峰值与内存峰值指标

**报告原文**："CPU Utilization：查询处理周期内 CPU 资源的**平均与峰值**利用率"；
"Memory Utilization：运行时堆内存及物理内存的**峰值占用**开销"（3.5）。

**现状**：Executor 采样执行期 CPU 平均值；内存为执行后单次采样（近似稳态值）。

**修改方案**：
1. `_CpuSampler` 输出 max 与 avg 两个值；内存采样移到执行期间（轻量线程），
   记录峰值；
2. ExecutionResult.metrics 扩展 `cpu_utilization_peak`、`memory_utilization_peak`
   （平均字段不变，向后兼容）；监控输出 metrics 节同步扩展；
3. 批次汇总报告增加峰值统计。

**涉及**：`executors/iotdb.py`（采样线程）、`normalize.py`（指标规范）、
`report.py`、schema、测试。

---

### D5（P1）：模块消融实验开关

**报告原文**："依次剥离 Query Analysis Agent、Execution Monitoring Agent 与
Knowledge Memory Agent 模块，定量分析各功能模块……的贡献度"（3.4.5）。

**现状**：无模块级开关（只能通过配置控制 LLM、证据 top-K 等，非模块剥离）。

**修改方案**：
1. RunnerConfig 增加消融开关（`ablation` 节）：
   - `no_knowledge`：决策不接收历史证据（≈剥离 KM 的决策输入）；
   - `no_monitoring_feedback`：执行后跳过监控判断，知识库只记原始指标
     （≈剥离 EM 的判断职能）；
   - `no_query_analysis`：使用预置的固定特征（≈剥离 QA）；
2. 每项剥离仍保持输出 schema 完整（对应字段 unknown/空），保证统计可比；
3. 文档给出消融矩阵与命令示例。

**涉及**：`runner.py`、各 Agent 输入的绕过路径、测试、文档。

### D6（P2）：动态演化工作负载 + Adaptation Performance 指标

**报告原文**："在实验过程中动态切换查询的时间跨度、设备密度、过滤谓词与聚合
模式，模拟真实工业场景下的工作负载漂移……验证系统对非平稳环境的自适应调整
能力"（3.4.4）；"Adaptation Performance：工作负载发生漂移后，系统收敛至新的
最优策略所需的查询迭代次数/时间"（3.5）。

**现状**：查询集为静态文件；无漂移注入；无收敛指标。

**修改方案**：
1. 新增负载编排工具 `scripts/make_drift_workload.py`：把查询集按特征分"阶段"
   （如 q1~q4 窗口为阶段 A 窄范围，q7~q11 窗口为阶段 B 宽范围聚合），
   输出带阶段标记的 .jsonl 查询序列（时间上交错/突变）；
2. 决策侧无需改动：漂移自适应本就由"历史证据相似度门控 + 评价表动态权重"
   （D1 完成后）支撑；
3. 新增 Adaptation Performance 测量：以策略序列为观测，定义"最优策略"为
   该阶段内累计成功率最高的策略；统计漂移点之后系统选中最优策略所需的
   查询迭代次数/时间（输出到批次汇总与 run_log 附加统计）。

**涉及**：负载编排脚本、报告统计扩展（`report.py` 或独立分析脚本）、文档。

---

### D7（P2）：策略切换跟踪实验（oracle 重合度）

**报告原文**："追踪记录系统输出的最优策略与实际物理最优策略的重合度"
（3.4.6）。

**现状**：无"物理最优"的测量手段。

**修改方案**：
1. 新增 oracle 测量模式（仅小样本实验使用）：对同一查询依次执行**全部适用
   候选策略**（等价 SQL/参数枚举），以实测延迟最低者为物理最优，写入 oracle
   结果文件；
2. 分析脚本比对系统选策略与 oracle 策略的重合度（按查询类型/维度统计）；
3. 明确开销提示：oracle 测量每查询执行次数 = 候选数，仅在抽样小样本启用。

**涉及**：`scripts/measure_oracle.py`（独立工具，复用 Executor）、
`scripts/analyze_tracking.py`、文档。

---

### D8（P2，说明性）：候选策略"生成"语义

**报告原文**："基于特征向量，映射并生成对应的候选策略解空间"（3.3）。

**现状**：候选 = 输入候选 ∩ 固定目录，目录内以需求评估做适用性过滤（效果近似
特征映射）；"禁止自行创造候选策略"的规格原则下，目录是封闭的。

**修改方案**（轻量对齐，不违背原则）：在目录中显式声明"特征适用性映射"
（如 time_pruning 维度仅当 has_time_filter 时进入候选解空间），使
`decide` 在未提供候选输入时也能**按特征自动生成适用候选集**（即目录映射），
表述与实现统一。无行为风险。

**涉及**：`catalog.py`（适用性映射表）、`context.py`（候选生成）、文档措辞。

|---|---|---|
| 1 | D1 + D2 | 报告核心机制（反馈驱动的权重调整）与特征表示的规范化，是后续实验的底座 |

## 四、风险与权衡（评审时注意）

1. D1 动态权重必须保持确定性（权重 = 反馈的确定性函数），否则实验不可复现；
   表级先验加分幅度需消融验证（建议可配置，默认温和）。
2. D2 特征向量与结构化特征并存，两者不一致的风险由"向量只由结构化特征
   确定性编码"保证（无独立事实来源）。
3. D4 峰值采样引入少量开销（采样线程），对极快查询的峰值意义有限——
   文档注明测量口径。
4. D6/D7 的"最优策略"定义需要论文口径明确（阶段内累计成功率最高 vs oracle
   实测最优），建议实验设计时先与导师对齐。
